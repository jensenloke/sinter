# Sinter v0.3.1

Sinter v0.3.1 makes multiple local harness profiles work without requiring the
user—or an agent—to remember a setup recipe.

## Automatic multi-profile setup

On the first operational run, Sinter detects `~/.claude/projects` and matching
`~/.claude-*/projects` stores. If it finds at least two and no config exists, it
creates a private `config.toml`, selects its `default` profile immediately, and
keeps normal discovery enabled for every other harness.

- Existing config files are never overwritten.
- Generated files use owner-only permissions on POSIX systems.
- Alternate Claude instances use `CLAUDE_CONFIG_DIR`, so shell aliases are not
  required for resume commands.
- `sinter config example` prints an editable configuration.
- `sinter help instances` gives humans and agents a complete, safe workflow.

## CLI contracts

Requested results and machine-readable output remain on stdout. Startup
notices and errors use stderr. Usage and validation failures return non-zero
exit codes, and help/version/config-example commands do not create config.

## Install

```sh
bun add --global @jensenloke/sinter@0.3.1
```
