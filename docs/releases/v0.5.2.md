# Sinter v0.5.2

Status: release candidate. Not tagged or published until the maintainer
approves; npm `latest` remains `0.5.1` until then.

Sinter v0.5.2 publishes the context-budget fitting and ledger maintenance work
merged after v0.5.1, and fixes the interactive menu hiding indexed sessions
from other directories.

## Fix: menu directory filter (#43, PR #44)

The interactive picker (`sinter` / `sinter menu`) silently scoped itself to the
launch directory whenever that directory had sessions, so a search for a known
session from another project reported `no session matches the search` even
though the ledger held it.

- The menu now opens on all directories. `sinter menu --all` is unchanged and is
  the default.
- `sinter menu --here` starts scoped to the launch directory; `^o` toggles
  between the two and preserves the current search.
- The title bar shows `directory: all` or `directory: <path>`; the key hint
  reads `^o this dir` / `^o all dirs`.
- A scoped search with no local matches now says how many matching sessions
  exist elsewhere and how to reach them; a scoped search with local matches
  notes the additional matches in other directories. Counts respect the active
  harness, ghost, and subagent filters.
- Shell completions (zsh, bash, fish) know `--here`.

## Feature: fit ports to target context budgets (PR #38)

Local ports, imports, and cross-harness resumes default to `--mode auto`. When
the target adapter reports a context budget, Sinter tries `full`, then `slim`,
then `compact`, and keeps the least destructive representation that fits.

- Named-instance targets (`harness@instance`) keep their exact binding through
  planning and writing.
- `send`, Cloud `push`, and serialized network metadata remain concrete-only and
  reject `auto`.
- The Devin adapter measures history in UTF-8 bytes, never splits a code point,
  enforces the strict 200,000-byte cap, and refuses to write if the capped
  history is still oversized.

## Feature: ledger backup, verify, and repair (PR #39)

```sh
sinter ledger backup [--output file] [--json]
sinter ledger verify [--json]
sinter ledger repair [--yes] [--no-backup] [--json]
```

- `backup` snapshots the on-disk ledger with `VACUUM INTO` (WAL-safe), refuses
  to overwrite existing files or follow symlinks, writes `0600`, and reports
  size and SHA-256.
- `verify` is read-only: schema version, required tables, SQLite and FTS5
  integrity, and missing or orphaned FTS rows keyed by
  `(harness, instance_id, native_id)`.
- `repair` verifies first, refuses when SQLite integrity has failed (restore a
  backup instead), takes a backup by default, and rebuilds only derived data
  (`sessions_fts`, `REINDEX`) inside one transaction. Sessions, aliases, pins,
  notes, tags, lineage, saved views, and capsule replay rows are preserved.

## Boundaries

Cloud protocol, authentication, quotas, repository binding, entitlements, and
the hosted owner-only service are unchanged. Native harness stores remain
read-only.

## Verification

- PRs #38, #39, and #44 passed macOS, Ubuntu, and isolated database-policy CI.
- PR #44 was additionally driven end-to-end in a real terminal against a
  synthetic ledger (default scope, `--here`, `^o` toggle, `--all`, narrow
