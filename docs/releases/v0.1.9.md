# Sinter v0.1.9

Sinter v0.1.9 keeps the ledger fresh automatically: every session-reading command refreshes it first, so you no longer have to run `sinter scan` to find a session.

## Added

**Automatic ledger refresh before session-reading commands.** Before `ls`, `search`, `show`, `rename`, `export`, `import`, `port`, `resume`, `relink`, or the interactive menu, Sinter now runs the same incremental scan that `sinter scan` does, silently, against every available harness store. Sessions created directly in a native harness between two Sinter invocations are visible on the next command instead of waiting for a manual scan.

The refresh is deliberate about noise and failure:

- It prints a single dim line (e.g. `(ledger: 3 new, 1 updated)`) only when rows actually changed; steady-state runs are silent.
- A store that fails to scan is reported as a dim warning and skipped — the command still runs against the stale ledger. The refresh never turns a healthy read into an error.

**Opt-outs for scripts and latency-sensitive use.** `--no-scan` (global flag) or `SINTER_NO_SCAN=1` skip the automatic refresh for a single invocation. `scan`, `setup`, `doctor`, and `privacy` are exempt: `scan` performs its own scan, `setup` asks before scanning, and `doctor`/`privacy` are diagnostics that should report the ledger as-is.

This complements the v0.1.8 write-path fix: that made *Sinter-written* targets resolvable immediately; this release makes *native-harness-created* sessions discoverable immediately.

## Validation

- New CLI tests: auto-scan populates the ledger before `ls` runs; it is disabled by default for hand-built test contexts; `--no-scan` and `SINTER_NO_SCAN=1` both skip it; `scan` and `privacy` do not trigger a second scan; a failing store is reported but never fails the command.
- Full automated test suite (521 tests).
- Full TypeScript checking.

## Installation

```sh
bunx @jensenloke/sinter@0.1.9
```

```sh

```
