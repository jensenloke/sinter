# Sinter v0.2.0

Sinter v0.2.0 turns the local session ledger into a practical daily workspace: faster continuation, durable organization, safer transfer inspection, scriptable output, and stronger diagnostics—without requiring an account or uploading transcripts.

## Find and continue work faster

**Return to recent work with fewer steps.** `sinter recent`, `sinter last`, and `sinter projects` surface resumable sessions and active working directories without opening transcript bodies. `sinter last --exec` resumes the newest match directly.

**Monitor new local activity.** `sinter watch recent|projects` refreshes a terminal view as harness stores change. Pipes and CI receive a bounded one-shot result by default; `--json` emits versioned NDJSON snapshots.

**Use native completions.** `sinter completion zsh|bash|fish` generates shell-native completion scripts without editing shell configuration.

## Organize the local ledger

**Bookmark and annotate sessions.** Pins, searchable tags, notes, and aliases remain local, survive rescans, and never modify or travel with native sessions.

**Save reusable views.** Named filters preserve harness, directory, recency, result-limit, ghost, and subagent choices for repeated workflows.

**Clean stale metadata safely.** Ghost housekeeping is preview-first and protects rows carrying aliases, pins, tags, notes, or lineage.

## Inspect transfers before trusting them

**Preview a port.** `sinter port ... --preview` reports the planned target and transfer impact without writing a target session.

**Inspect provenance.** `sinter thread` shows ordered port lineage and selects the newest surviving resumable tip.

**Compare structure without printing content.** `sinter compare` inventories entry types, models, tool records, and right-minus-left differences while keeping transcript text out of its output.

**Handle large transcripts.** `sinter show --tail` renders only the newest entries; `sinter show --ndjson` streams versioned metadata and entries one record per line.

## Diagnose and automate safely

**See actual adapter readiness.** `sinter capabilities` distinguishes package loading, store detection, read/write support, and native resume availability for all seven harnesses.

**Inspect setup without guessing.** Configuration inspection, versioned scan output, and privacy-safe doctor reports make support cases reproducible without including paths, prompts, IDs, or transcripts.

**Use stable machine interfaces.** New JSON, NDJSON, and error contracts are versioned. Existing machine-output shapes remain unchanged for compatibility.

## Privacy and reliability

- On POSIX systems, the SQLite ledger and its WAL/SHM sidecars are restricted to the current user (`0600`), including ledgers created by older releases.
- Telemetry remains disabled by default, requires explicit opt-in, contains no session content, and is suppressed in CI and non-interactive commands.
- Historical tool calls remain inert during ports unless explicitly enabled for a compatible target.
- OpenCode → Codex has an end-to-end regression gate covering context, immediate resolution, lineage, source-store immutability, and carry recovery.
- The release candidate passed 614 tests / 8,734 assertions, TypeScript checking, macOS and Ubuntu CI, package inspection, and isolated Bun/npm global installs.
- A real OpenCode → Codex port was resumed successfully and retained usable conversational context.


```sh

```
