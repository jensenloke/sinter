# Sinter v0.4.0

Sinter v0.4.0 adds explicit updates, safer multi-instance discovery, optional
Cloud device identity, and stronger local/direct-transfer foundations while
keeping transcript uploads disabled.

## Updates and multi-instance setup

- `sinter update --check` compares the installed CLI with npm without changing
  anything; `sinter update` installs an exact published version through the
  detected Bun or npm global layout.
- Newer local builds are never downgraded unless `--force` is explicit.
- Interactive actions show each user's qualified `harness@instance` identity,
  including same-harness targets.
- Existing `~/.claude-*` stores remain create-only automatic discoveries.
- `sinter config discover-shell` explicitly previews simple custom
  `CLAUDE_CONFIG_DIR=<path> claude` aliases. Raw aliases are suppressed and an
  existing config is never overwritten.

## Optional Cloud device identity

Sinter Cloud remains a private alpha for existing approved members. Public CLI
use requires no account, and new Cloud accounts cannot be created in this
release.

```sh
sinter login
sinter devices register --name "My Mac"
sinter devices list
sinter devices pending
sinter devices approve <request-id>
```

The CLI stores device private keys locally, uses separate P-256 encryption and
signing keys, and requires an existing device's signature before enrolling a
subsequent device. Account and device commands do not scan local sessions or
create profile configuration. Cloud transcript uploads remain disabled.

## Local and direct transfer

- Named instances use `(harness, instance, native-id)` throughout discovery,
  ledger identity, resume, porting, and direct encrypted transfer.
- `sinter send` and `sinter receive` move sanitized conversation context over a
  one-use encrypted LAN/Tailscale channel without requiring Cloud sync.
- Historical tool calls remain inert unless explicitly enabled for a compatible
  target.
- Codex function-call arguments remain readable when ported to Devin.

## Verification

The release gate covers the full test suite, TypeScript, CLI and Cloud builds,
schema policy tests, package inspection, and isolated Bun/npm global-install
rehearsals. Sinter remains useful without an account and does not upload coding
sessions in this release.

## Install

```sh
bun add --global @jensenloke/sinter@0.4.0
# or

```
