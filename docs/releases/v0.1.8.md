# Sinter v0.1.8

Sinter v0.1.8 fixes Codex ports that resumed without any source-session context, and makes newly ported sessions resolvable immediately.

## Fixed

**Codex rollouts now group messages into turns, so `codex resume` reconstructs the ported conversation.** The writer now emits the dual-track shape Codex's legacy resume path expects: every `response_item` carries `internal_chat_message_metadata_passthrough.turn_id`, turns are delimited by `turn_context` records whose payload carries the turn id, and assistant messages carry a `phase`. Each line also carries a monotonically increasing `ordinal`. Ports are round-trip verified: the rollout is read back and the source conversation (prompts, replies, tool calls, results) is present and turn-grouped.

**Newly written targets land in the ledger without a separate `sinter scan`.** `port`/`write` and cross-harness `resume` now upsert a `SessionSummary` for the target they just wrote, so the new session is resolvable by prefix (e.g. `codex:<id>`) immediately after the port. `sinter scan` remains the bulk reindex tool; both paths write the same rows, so a later scan is a no-op for sessions that are already correct.

## Validation

- Round-trip test: port a multi-turn session to Codex, read the rollout back through the adapter, and confirm the conversation content and turn grouping survive.
- CLI tests: after `port --to codex` and after `resume --in codex`, the fresh target resolves through the ledger without a scan.
- Full automated test suite.
- Full TypeScript checking.
