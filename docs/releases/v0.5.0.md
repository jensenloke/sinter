# Sinter v0.5.0

Status: stable release preparation; owner-only Cloud infrastructure enabled and
physically verified, not tagged or published.

Sinter v0.5.0 adds locally encrypted Cloud session sync while keeping the CLI
fully useful without an account. The open-source client is intended to be public;
the hosted service remains owner-only during the initial test cycle.

## Encrypted session sync

```sh
sinter cloud push <id-prefix> --preview
sinter cloud push <id-prefix> [--mode compact|slim|full] [--to all|<device>]
sinter cloud list
sinter cloud inspect <capsule-id>
sinter cloud pull <capsule-id> --to <harness@instance> --cwd <repository-root>
sinter cloud delete <capsule-id>
```

- Push reads but never modifies the source harness store.
- Repository identity and working directory are sanitized before local encryption.
- Only canonical capsule ciphertext and bounded content-free routing metadata are
  retained remotely.
- List reveals no title, prompt, transcript, repository, path, native ID, key, or
  signed Storage URL.
- Inspect and pull verify exact bytes/hash, active sender and recipient identity,
  and ECDSA signature before local decryption.
- Pull repeats repository checks before creating a new session in the exact target
  instance. Dedicated repository and missing-commit overrides remain explicit in
  provenance; dry-run consumes no replay.
- Delete remains available to an authenticated active owner device even if uploads
  are disabled or the account is suspended.

## Service security

- Every capsule API request requires paired Auth0 tokens and a device signature
  over the exact method, path, body hash, timestamp, and one-use nonce.
- Request nonces are claimed durably and cleaned through the secret-protected
  daily capsule maintenance route.
- A private Supabase Storage bucket holds encrypted objects under opaque IDs.
- Service-role-only RPCs reserve/finalize storage atomically, enforce active owner
  entitlement and 16/64 MiB caps, account for retained/reserved bytes and sessions,
  and coordinate retryable Storage cleanup.
- Finalization streams and hashes the uploaded object server-side before quota is
  moved from reserved to retained.
- Admin upload entitlement can be changed only while the exact global feature gate
  is enabled and after super-admin reauthorization, typed confirmation, and an
  audit reason. Defaults remain off.
- Public signup remains closed and no recovery escrow exists.

## Compatibility

Direct LAN/Tailscale transfer remains available. Its repository-bound v2 payload
and Cloud capsules share the same sanitized session-transfer schema, target
repository checks, exact-instance writer, and provenance behavior.

The outer synthetic capsule vectors and diagnostic commands remain backward
compatible; real-session and synthetic payload schemas cannot be confused.
