# Sinter v0.1.5

Sinter v0.1.5 adds automatic update notifications on top of the cross-harness portability, Devin CLI support, large-session safeguards, and interactive workflow improvements shipped since the initial public release.

## Highlights

### Devin CLI support

Sinter can now:

- Discover and index local Devin CLI sessions.
- Read Devin's SQLite message trees into SIF.
- Port sessions from other harnesses into Devin.
- Preserve conversation topology, usage, workspace roots, and lineage.
- Resume imported sessions with `devin --resume <id>`.
- Keep historical tool calls inert unless `--live-tools` is explicitly enabled.

Sinter now supports seven harnesses:

| Harness | Read | Port target | Native resume |
|---|---:|---:|---:|
| Claude Code | Yes | Yes | Yes |
| Codex CLI | Yes | Yes | Yes |
| Devin CLI | Yes | Yes | Yes |
| opencode | Yes | Yes | Yes |
| ZCode | Yes | Experimental | Unverified |
| Oh My Pi | Yes | Yes | Yes |
| pi | Yes | Yes | Yes |

### Safer large-session transfers

Sinter now protects Devin from oversized imported histories.

The issue was discovered with a Codex session carried through OMP into Devin:

- Approximately 4,900 active historical messages.
- 9.25 MB of active conversation data.
- Devin's automatic compaction failed.
- Repeated retries expanded the database to 19,627 nodes and 52 MB.
- Subsequent prompts failed with `invalid_argument`.

Sinter now:

- Limits cross-harness Devin history to approximately 200 KB.
- Retains the opening objective and latest conversation tail.
- Adds a visible note explaining omitted history.
- Keeps the complete source available through Sinter carry data.
- Removes provider-bound reasoning signatures and model state when crossing harnesses.

The fix was validated against the affected session on a DGX Spark. The repaired session resumed and completed a real inference successfully.

### Reliable Claude-to-Codex resumes

Imported Claude sessions no longer carry incompatible Anthropic runtime configuration into Codex.

Sinter preserves the conversation while allowing Codex to use its configured target provider and model. This fixes startup failures such as:

```text
Model provider 'anthropic' not found
```

### Interactive command previews

The action screen displays the equivalent CLI command for the selected operation:

```sh
sinter show <id>
sinter resume <id> --exec
sinter resume <id> --in devin --exec
```

This makes the TUI easier to understand and lets users reuse commands in scripts.

### Automatic update prompts

Interactive Sinter runs check npm for updates at most once every 24 hours.

When a newer release is available, Sinter prompts before changing the global installation:

```text
Sinter 0.1.6 is available (current 0.1.5). Update globally now? [Y/n]
```

If accepted, Sinter runs:

```sh
bun add --global @jensenloke/sinter@latest
```

Update checks never prompt in CI, scripts, piped output, help or version commands, or offline environments. Declining suppresses another prompt for 24 hours.

Disable the check for one invocation:

```sh
sinter --no-update-check
```

Or disable it through the environment:

```sh
export SINTER_NO_UPDATE_CHECK=1
```

## Installation

Run once:

```sh
bunx @jensenloke/sinter@0.1.5
```

Install or upgrade globally:

```sh
bun add --global @jensenloke/sinter@0.1.5
```

Verify and refresh:

```sh
sinter --version
sinter scan
sinter doctor
```
